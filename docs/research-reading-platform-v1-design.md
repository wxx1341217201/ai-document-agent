# 科研与书籍阅读 AI 平台第一版设计

日期：2026-10-20。

状态：Q1—Q19 及整体设计已确认，用户已明确要求开始开发。本文保留产品设计基线；本次实现、使用入口和验证状态见 [实现说明](reading-v1-implementation.md) 与 [开发记录](reading-v1-development.md)。设计目标不等于已经通过全部验收。

## 1. 产品定位与首个闭环

服务个人科研与深度阅读用户，围绕选定资料和明确阅读目标，生成有原文依据、可以追问、编辑和继续补全的阅读笔记。

首个验收任务使用用户熟悉的《脂砚斋评石头记》：围绕“风月宝鉴”相关内容，梳理情节与评点，区分原文事实、评点观点和系统推论，形成带引用的阅读笔记。具体结论以选定版本的真实原文为准。随后以一组论文复验同一流程。

用户流程：选定资料 → 描述阅读目标 → 后台分析并展示进度 → 阅读笔记及引用 → 追问、人工编辑或继续补全 → 导出 Markdown。

## 4. 三范式接力结构

~~~mermaid
flowchart TD
    U[阅读目标与选定资料] --> O[根编排器：任务、范围、预算、版本]
    O --> D{目标复杂度}
    D -->|简单定位| R[Retrieval-First：检索取证]
    D -->|多步分析| P[Plan：拆解必需目标与步骤]
    P --> R
    P --> A[ReAct：多轮工具交互子任务]
    R --> V[核验目标覆盖、证据支持与引用]
    A --> V
    V -->|明确缺口且仍有预算，最多一次重规划| P
    V -->|目标满足或进入收尾| F[发布版本化结果与缺口]
    F --> N[阅读笔记草稿：全部完成、部分完成或无可靠结果]
~~~

Plan-Execute-Reflect 负责复杂任务的规划、委派和反思重规划；Retrieval-First 提供轻量取证能力；ReAct 完成需要多次搜索、读上下文、核对文档信息的子任务。按目标需要接力，满足目标即可提前结束。

根编排器统一发布整个任务的结果。阶段返回结构化子结论、证据和缺口；阶段执行成功不等于用户目标已经完成。复杂目标首次规划后保留稳定标识，重规划可以改变步骤，不能删掉未满足要求来获得“全部完成”。

协议可继续使用 COORDINATED 表示编排入口，在其内部自动选择简单或复杂路径；它表示编排方式。原三种独立模式保留兼容性及对照验收入口。技术交接细节见 [多范式协同设计](multi-paradigm-coordination-v1-design.md)。

## 5. 资料边界、解析与覆盖

任务保存知识库、明确的文档 ID 集合及所依据的资料版本。知识库级选择在任务开始时展开为明确文档集合；以后新上传资料不会自动进入该任务。扩大范围形成明确的范围变更记录，并重新检查受影响目标。

向量、关键词、融合及重排的候选都必须限定在资料白名单内，再对最终证据做归属校验。仅在全库召回后丢弃越界片段，会损失选定资料的有效召回，需要在候选获取阶段就应用范围限制。文档信息、片段上下文工具也使用同一边界。

文档内容作为阅读数据，不能修改任务目标、工具权限或资料范围。人工笔记及系统推论单独标明来源，不能自动变成书籍原文证据。

PDF 页码明确指物理文件页；TXT 缺少页码时显示段落或片段定位。章节、评点作者和正文归属以可核验信息为准；无法可靠识别时标记待确认，并保留原文供核对。图表、复杂公式和扫描识别缺口进入覆盖报告。

专题问答检查必需目标的证据支持。全面总结额外保存材料及阅读单元清单，区分“已建立索引”“已检索”“已阅读分析”等状态；索引完成不能代替阅读覆盖。存在未审阅的重要材料或未可靠解析的必需内容时，明确报告部分完成。全部完成不要求逐段引用，但需要全部主要目标与必需覆盖项通过检查。

全面阅读还需要有界的阅读单元枚举与顺序读取能力，作为现有搜索、上下文及文档信息工具的补充。分页游标和已审阅范围进入检查点，跨轮继续；仅枚举到某片段不能标记为已分析。实际读取与模型处理都计入本轮额度，因此整书分析可能需要多轮。

## 6. 执行预算与排队

| 项目 | 首版规则 |
| --- | --- |
| 每轮总时限 | 最多 180 秒，满足目标可提前结束。 |
| 大模型生成请求 | 最多 8 次，规划、ReAct、反思、修复、重试、最终整理统一计数。 |
| 工具调用 | 最多 12 次，按实际受控操作计数，阶段包装不重复计数。 |
| 重规划 | 最多 1 次，仅围绕明确缺口调整。 |
| 长任务并发 | 1；后续任务进入持久化队列。 |
| 收尾预留 | 提前保留时间和至少一次生成请求额度。 |

工程建议：180 秒从阅读任务实际开始执行时计算，排队时间单独展示；解析入库采用独立异步任务。初始可在第 140 秒进入收尾，单次调用上限 35 秒，并同时受根任务剩余时间限制。这两个初始值需要实测校准。

生成请求发往提供方前扣减额度，客户端内部重试也必须纳入。Embedding、重排和检索内部请求分别限制超时和重试，并记录实际用量；生成请求数不等于所有外部请求数或固定金额。各范式切换、反思和异常恢复均不能重置本轮已用额度。

不足以安全发起下一次请求时，使用已核验子结论整理交付。截止后停止发起外部调用；没有最终模型调用额度时，可以直接展示有界的可靠阶段产物及缺口。

## 7. 状态与完成度

| 维度 | 含义 |
| --- | --- |
| 执行状态 | 排队、运行、等待恢复、成功、失败、取消等运行事实。 |
| FULL | 全部必需目标及必要覆盖项满足，发布结论具有合格证据。 |
| PARTIAL | 已形成可交付的可靠子结论，其余目标和缺口明确。 |
| NONE | 尚无可交付的可靠子结论；只有搜索命中或工具日志也属于 NONE。 |

运行失败可以同时保留已经发布的 PARTIAL 结果。没有完成覆盖评估的旧任务沿用原展示语义，不补造 FULL。模型给出的语义覆盖判断接受来源、范围、哈希和引用绑定的代码校验约束；未核验目标不得计为满足。

页面展示已完成分析、尚未解决问题、缺口原因、资料范围、实际步骤和本轮消耗。已有结果始终可读，补全失败或中断不会覆盖历史可靠版本。新增界面遵守 [DESIGN.md](../DESIGN.md)。

## 8. 任务、证据与笔记的数据关系

| 对象 | 职责与关键数据 |
| --- | --- |
| 阅读会话 | 容纳连续问题、关联任务和资料范围选择。 |
| 阅读任务 | 稳定任务 ID、原始目标、必需目标、资料范围、父任务或前序任务关联。 |
| 执行轮次 | 每次初始分析或主动补全的轮次 ID、截止时间、已用额度、执行状态和中断原因。 |
| 阶段检查点 | 计划版本、子目标、依赖指纹、阶段产物、来源绑定、当前位置。 |
| 证据登记 | 知识库、文档与资料版本、解析版本、片段、内容哈希、摘录及定位；根任务统一编号。 |
| 结果版本 | 不可变的已交付答案、完成度、目标覆盖、缺口和引用快照。 |
| 阅读笔记 | 独立可编辑成果，关联任务及结果版本，区分当前笔记与待采纳 AI 草稿。 |
| 笔记修订 | 人工或 AI 来源、基础版本、修订内容、采纳状态和历史记录。 |

阶段状态与产物在同一事务提交，成功后才发送进度。利用任务租约、runToken、版本检查及幂等键，阻止旧工作线程或重复点击发布冲突结果。历史摘录支持回顾当时依据；打开当前原文时明确显示版本差异或来源不可用状态。

启动扫描或租约过期发现中断的协同任务时，将其标为待恢复并保留检查点，等待用户恢复操作；新协同路径不能被通用恢复扫描器自动重新执行。

## 9. 四类后续操作

| 操作 | 任务目标与预算 | 结果和复用规则 |
| --- | --- | --- |
| 继续补全 | 同一任务、原必需目标；新轮最多 180 秒，重新分配本轮次数额度。 | 复核资料及依赖，复用有效阶段，重点补缺口，发布新结果版本。 |
| 提出新问题 | 同一会话下创建关联任务，建立新目标，沿用当前选定范围。 | 相关证据核验后复用；原任务的目标、完成度和结果独立保存。 |
| 异常恢复 | 手动恢复中断轮次；沿用原轮计数与截止时间。 | 有效已保存阶段可复用，未完成阶段重做；已过截止时间则先整理成果，后续计算需要用户开启补全轮。 |
| 编辑与采纳 | 用户编辑独立笔记；AI 更新基于明确的基础版本。 | 新版 AI 草稿等待采纳，展示差异；并发编辑检测版本冲突，历史修订保留。 |

资料更新时，旧笔记标明对应版本。新分析复核内容哈希、解析版本和依赖指纹；变化影响到的阶段及下游判断重新计算。资料范围扩大需要用户决定，不能作为自动重规划的隐含动作。

## 10. 开发分解与验收关口

| 阶段 | 工作 | 验收关口 |
| --- | --- | --- |
| A：范围与证据 | 选定文档白名单、阅读单元、来源版本与摘录、结构化目标和覆盖报告。 | 各检索与工具路径均不可越界；引用可回到选定版本；未知归属及解析缺口可见。 |
| B：跨范式编排 | 取证阶段适配、ReAct 子任务、Plan 委派、共享预算与有界反思。 | 同任务真实发生需要的阶段交接；简单任务可提前结束；重试和重规划均受总预算限制。 |
| C：可靠长任务 | 持久化队列、阶段检查点、执行与交付状态拆分、结果版本、继续补全与手动恢复。 | 崩溃、超时、取消、旧线程回写与重复请求均不会丢失已发布成果或重置额度。 |
| D：阅读成果 | 笔记、引用查看、编辑与草稿采纳、关联追问、历史版本及 Markdown 导出。 | 用户修改保留；源文件变化可追踪；刷新或离开页面后可重新打开任务与笔记。 |
| E：真实验收 | 固定 20 题、现有流程对照、论文组复验、规模与用量测试。 | 达到 Q16 门槛，所有关键工程场景通过；报告实际成绩、耗时、覆盖与消耗。 |

复用现有 AgentRouter、三种引擎、检索服务、工具注册表、异步执行与进度基础。增加受限子阶段上下文、统一阶段产物与笔记存储；调整现有结果模型和恢复路径。所有数据库变更新增 Flyway 迁移，保留已应用迁移与原模式兼容性。

验证先使用脚本模型覆盖阶段交接、目标不可被重规划删除、范围约束、预算、阶段事务与恢复，再进行真实资料评测。20 道阅读题衡量内容质量；队列、恢复、版本冲突等工程用例单独验收，不能充当答题成绩。

## 11. 首批评测与当前未验证项

候选问题见 [阅读验收题草案](research-reading-v1-acceptance-cases.md)。需要先依据用户选定的真实版本标注答案、原文、可接受推论与缺口，再冻结正式 20 题。没有金标或尚未运行的题目不计成绩。

现有模式与新方案使用同一资料、范围和题集；记录模型、提示词、索引及检索配置，报告核心要求满足情况、引用支持、越界情况、完成度、耗时及实际用量。参数变化单独记录。论文组复验另保留资料快照和判定依据。

目前未测得新方案的准确率、延迟、模型费用、OCR 实际质量或 2,000 文档／10 万片段容量结果。Q12 为验收目标，Q16 为通过门槛。协同阅读工程实现已进入本地验证；迁移只在隔离测试库与开发副本执行，尚未发布云端新功能。20 题需先完成真实原文标注与冻结，之后再按本节要求验收。
