## 本轮改动

三种 Agent 采用共享的结构化事实草稿：每项事实绑定当前证据 ID 和原文句段。`ClaimEvidenceValidator` 从实际展示的原文中定位字符位置，保留来源版本 SHA-256、展示快照 SHA-256、真实引文及服务器提供的文档元数据，随后由服务端渲染引用。拒绝跨库、未知 ID、伪造原文、额外字段和明确数字冲突。原文换行被模型折叠时，仅允许确定性定位等价空白，记录的仍是真实原文及其位置。

ReAct / Plan 的 `ClaimSupportVerifier` 单独检查每项事实绑定的原文，区分 SUPPORTED / CONTRADICTED / UNKNOWN。检查主体、说话者、事件、数量、单位、时间和比较输入；没有提供推理字段。格式错误只带安全枚举修复一次，原始错误输出不回放。RF 在第二次调用中进行复核并直接修复结构化草稿。运行时模型判断只提供反馈，不代替独立人工评分。

校验器还获得绑定引文前后各最多约 240 字符的原文，用于消解主体、说话者和场景；这些上下文必须来自同一实际可见快照，版本/展示哈希不一致时拒绝，仍受证据 token 上限约束。上下文不能替代引文中的谓词、数量或单位证据。

检索候选池与最终上下文分离，生产候选池为 20。索引命中须经数据库 KB、文档、READY 状态复核后填充最终名额；已失效的索引命中不能挤占有效证据。子查询保留独立名额，并使用用户问题与候选文本进行有界词项排序。书名/作者意图在定位文档后读取 0..1 号原文头部，作者不取自上传者。

ReAct / Plan 将来源登记表与生成窗口分开。登记最多 80 个来源，每个来源最多 8,000 字符；活动窗口继续受原片段数和 8,000 token 限制。来源 ID 不复用、不重新编号；移出窗口的来源可重新展示并恢复原 ID。前缀扩展须保持来源元数据和版本一致。只有已展示来源可以授权相邻检索，最终引用只能使用当前窗口。

ReAct 将旧工具响应正文替换为保留配对的摘要，在当前窗口统一展示证据；Plan 综合和校验只使用选中窗口。窗口预算包含实际展示标题及引用 ID 开销。模型和工具次数、截止时间及 Plan 最多一次重规划均保持原上限。

RF 保持每轮最多 2 次模型调用：草稿后，按结构化缺口至多补检一次，再进行复核与修复；已绑定子目标的来源优先保留，补检前后复用相同引用 ID。第二次输出仍需服务端验证，PARTIAL 不能完成任务；INSUFFICIENT 则输出不含事实断言的明确拒答，是否正确仍由 benchmark 独立判定。ReAct 在原 6 次模型调用内完成校验/一次答案修复；Plan 使用原 12 次模型预算。部分事实缺失的草稿不能仅追加免责声明后被认定为完成。

RF 为结构化协议及复核草稿额外预留 1,024 token，并在每次调用前校验真实 system/user 文本的 token 数。缺口查询根据当前源文语言生成，避免中文用户问题在英文资料中继续用笼统中文查询。检索提示不包含任务事实或专用人物映射。

结构化兼容只规范化单一外层 JSON 代码围栏，以及事实文本中已经在该事实支持列表绑定的重复引用标记。围栏外额外文字、未知 ID、伪造引文和 schema 额外字段仍拒绝。ReAct 无工具的收尾与校验调用启用 JSON 输出；独立子查询可批量提出，保留原调用预算。

## 观测与来源审计

新增独立诊断 journal，记录实际查询、候选/文档/排名、来源过滤、窗口保留/移出、模型输入哈希及实际提供的来源 IDs、事实与原文位置、支撑判断。最终版本还记录逐片段输入前缀长度/hash，校验调用记录实际引用句段，避免把登记表全集误写成每次模型输入。普通生产请求使用 NO_OP probe，不输出原始问题或证据日志。详细 journal 只由显式本地 benchmark probe 收集，不保存隐藏推理。

Runner 冻结所有应用 class（含内部类）的 SHA-256，结束时复核，并冻结诊断文件哈希。Audit 复算来源、结果和评分，校验诊断文件；旧报告缺少新增字段时继续兼容。未修改固定任务集、事实白名单、人工评分政策或历史报告。

## 运行与配置

```powershell
.\mvnw.cmd '-Dmaven.compiler.fork=true' test
.\scripts\run-agent-benchmark.ps1 -Mode Live `
  -ReportDirectory reports/m19c-citation-reproduce -Rerank $false -VerifyPlanEvidence $true `
  -AgentDeadline 120s -ModelTimeout 30s -MaxConsecutiveErrors 10 -MaxRunSeconds 3600 -UseHttpsProxy
```

由于目标未达标，且存在 7 条原自动通过任务回退，新协议默认关闭：`AGENT_STRUCTURED_ANSWERS=false`、`AGENT_PLAN_VERIFY_EVIDENCE=false`。明确实验时可设为 true；`AGENT_MAX_REGISTERED_SOURCES=80`、`RAG_RETRIEVAL_CANDIDATE_TOP_K=20` 控制资源边界。benchmark 脚本默认显式传入三模式 `StructuredAnswers=true` 和 `VerifyPlanEvidence=true`，可通过同名开关做对照。API 仍返回原有最终答案、引用、步骤和状态；结构化草稿是内部协议。凭据继续读取现有环境，不进入命令、报告或新增文件。

切换应用默认值后完成了只读 Preflight：benchmark 实际启用三模式结构化协议和 Plan 校验，534 个应用 class、模式配置、固定任务及全部 249 个来源与最终评测一致。预检没有执行任务或调用模型，不增加成功率证据。[配置核对原件](../reports/m19c-citation-20261018/rollout-preflight-comparison.json)。关闭协议仅用于当前代码对照，不能当作旧代码版本的精确回放。

正式验收仍要求独立人工审查冻结标签及全部答案/事实/引用。无人审时保持 N/A；不得使用运行时验证器或者字符串命中率冒充人工复核。
