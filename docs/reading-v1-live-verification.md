## 联调发现与修复

1. 项目原有 `.env` 开启了 Cohere 重排。第一次请求沿用该配置并收到拒绝响应。该目的地未包含在本次授权中，发现后已停止该调用，并向用户说明。新增阅读模块独立的 `READING_RERANK_ENABLED`，默认 false；不会因旧模块启用了重排而自动外发到它。后续联调只使用已授权的两个外部服务。
2. 初次反思同时看到了摘录与未摘录正文，容易为复合结论补齐摘录未覆盖的细节。改为按每条候选自己的 `supports.quote` 检查；普通专题核验不再接收整段未摘录正文。全文阅读单元仅供覆盖与冲突核查。再次实际回答已为复合情节补齐不同摘录。
3. 重规划会换一种措辞重复已有结论。增加了增量分析约束：要求仅补缺口或新反证，反思可撤回重复；但真实第 2 轮仍有重复，因此该质量问题尚未解决。当前不使用文本相似度擅自合并有分歧的学术解释。
4. JSON 中较小的 long 与数据库重载后的 int 节点会产生不相等的脏检查，导致一次操作多次更新与版本号跳增。真实 MySQL 回归先重现了“返回版本 1，实际版本 3”，再通过统一 JSON 解析后的数字节点类型修复。新增测试也检查保存返回版本、再次读取版本及结果表不被重复 UPDATE。
5. 模型一边列缺口、一边把全部目标标成已满足。根目标 G0 现在受确定性约束：仍有缺口时保持待完成，避免目标标签与 PARTIAL 相矛盾。
6. 一条坏引用会中断整批。现改为逐条排除不合格候选，不将其交给语义核验，保留合格部分；公开阶段记录给出拒绝码，不公开未核验草稿。该目标会强制保留缺口，模型不能仍把它标成全部完成。新增回归覆盖伪造引用和好、坏引用混合一批；未放宽逐字摘录、长度或范围校验。
