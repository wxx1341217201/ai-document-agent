# 协同阅读 V1：实现与本地验证

日期：2026-10-20。产品依据为 [19 项设计决策](research-reading-platform-v1-design.md)，界面依据为 [DESIGN.md](../DESIGN.md)。本次为开发交付，尚未发布到 ECS。

## 使用入口

侧栏「阅读笔记」→ 选择知识库 →「新建阅读任务」。知识库详情和文档详情也可通过「主题阅读」进入。选择同一知识库中 1–20 份已就绪资料，填写阅读目标后提交。

任务进入持久化队列，一次执行一个长任务。离开页面不会取消后台工作；从任务列表重新打开，可查看结果、原文快照和独立笔记。旧聊天入口的三种模式继续保留。

- 「继续补全」：原任务的新一轮，重新分配额度，复用仍有效的成果。
- 「恢复本轮」：中断轮次的手动恢复，保留原截止时间与计数。
- 「提出新问题」：同一阅读会话下创建关联任务，沿用资料范围，保留原任务。
- 「补充资料」：显式扩大范围并开启新一轮，不能由模型自动扩大。
- 笔记引用对应的资料变化后，「基于更新资料重新分析」可重开原任务，包括上一次已经 FULL 的任务；旧结果和笔记仍保留。

结果的 FULL / PARTIAL / NONE 与任务是否结束分别展示。初次可靠结果可填入空白笔记；之后 AI 新结果都作为待采纳草稿。人工笔记可以逐段采纳、对照、编辑、查看修订和导出 Markdown。编辑区保留独立基础版本，遇到 409 时保留本地修改，等待用户对照合并。

## 实际架构

本次新增 `reading` 业务模块和 `/api/v1/reading/tasks` 接口，没有给旧 `AgentMode` 或旧聊天协议添加第四个枚举值。这样独立笔记、结果版本和恢复语义可以形成完整流程，同时保持旧三种模式兼容。

`ReadingCoordinator` 在同一个任务及检查点中执行三类阶段：简单问题走检索、候选分析、核验；复杂问题先规划必需目标，再取证并进行有界 ReAct 工具循环，反思后至多针对缺口重规划一次。这里是新的受限阶段适配器，复用原有 `HybridRetriever`、ChatClient 配置和 `ClaimEvidenceValidator`；没有把原来三个顶层 Agent 串行调用，也没有复用它们各自的完整预算。

每轮共享 180 秒、8 次生成请求、12 次工具、一次重规划；生成 SDK 重试为 0。工具许可和生成许可都在发出请求前写入检查点。正常工作提前保留两次生成和一次最终来源核验的额度，单次外部调用最多等待 35 秒且受根截止时间约束。Token 按提供方返回值记录；生成次数不是全部外部请求数，也不换算为未经核实的费用。

检索入口将文档白名单传给向量、关键词索引，在排序前过滤，融合后再次检查。取回片段还会与数据库正文比较；候选结论要通过编号、资料版本、精确原文摘录和语义核验后才能发布。模型不能删除原始目标 G0，不能修改资料范围。反思可以撤回被新上下文推翻的旧结论。

全面阅读使用有界的顺序读取和持久化游标。一个超长片段会分段处理，未审阅文本不跳过；只有被核验为已审阅的单元才能推进覆盖。建立索引或搜索命中不会直接增加阅读覆盖。

新任务列表使用分页和摘要投影，避免读取完整检查点与结果 JSON。来源指纹使用每页 2048 行的版本元数据投影，不在任务提交时扫描全文。任务、结果版本、笔记和笔记修订都使用独立实体及 DTO。

## 持久化与迁移

新增 Flyway V17：`reading_task`、`reading_result`、`reading_note`、`reading_note_revision`、`reading_dispatch_lock`。全局数据库调度锁限制一个长任务；租约、runToken 和乐观版本阻止旧线程发布。过期任务标为待手动恢复，不由旧 Agent 的恢复扫描器重跑。

结果版本保存当时的目标、范围、结论、缺口、覆盖、消耗和原文快照。笔记保存自己的引用账本，修订记录保存旧账本。导出附带引用快照，源文件更新或暂不可用时仍能回顾历史依据。范围变化只重建受影响证据，保留仍有效的阶段产物。

V17 已在隔离测试库和隔离开发副本验证。原业务数据库、云端镜像与数据卷未在本次开发中修改。

## 接口

所有任务、结果和笔记访问都要带 `knowledgeBaseId`。任务创建支持 `Idempotency-Key`；状态操作带 `expectedVersion` 和 `expectedRoundNo`，笔记编辑使用独立的 `expectedVersion`。

| 方法与相对路径 | 用途 |
| --- | --- |
| POST `/reading/tasks` | 选择资料、创建后台任务 |
| GET `/reading/tasks` | 按知识库分页，可选 sessionId |
| GET `/reading/tasks/{id}` | 状态、目标、阶段、覆盖和用量 |
| POST `/reading/tasks/{id}/continue` | 新轮补全 |
| POST `/reading/tasks/{id}/resume` | 原轮手动恢复 |
| POST `/reading/tasks/{id}/cancel` | 按轮次取消 |
| POST `/reading/tasks/{id}/scope` | 明确确认扩展资料 |
| POST `/reading/tasks/{id}/refresh-sources` | 来源变化后重建受影响分析 |
| GET `/reading/tasks/{id}/results[/{resultId}]` | 分页版本列表或不可变结果 |
| GET / PUT `/reading/tasks/{id}/note` | 读取或编辑独立笔记 |
| GET `/reading/tasks/{id}/note/revisions[/{revisionId}]` | 修订列表或历史版本 |
| GET `/reading/tasks/{id}/note/export` | UTF-8 Markdown 与引用快照 |

以上路径均位于 `/api/v1` 下。新页面使用 1.5 秒的有条件状态轮询，不依赖旧聊天 WebSocket。

## 可重复的本地验证

要求 Java 21、Maven、Node，以及现有 Windows MySQL 容器 `ai-agent-mysql`。私有配置继续由被忽略的 `.env` 和 `secrets/` 管理。

```powershell
$env:JAVA_HOME = 'D:\Java\jdk-21'
./scripts/test-reading.ps1             # 独立临时库，阅读测试，结束后自动清理
./scripts/test-reading.ps1 -AllTests   # 使用同样隔离方式跑后端全量测试
mvn package                          # 正常打包；未提供测试库配置时隔离数据库测试会明确跳过
cd frontend
npm run typecheck
npm run lint
npx vitest run --maxWorkers=2
npm run build
```

单独的开发副本可按以下方式准备，默认只复制原业务库的表结构、Flyway 历史、知识库 8、文档 15 及其 1125 个片段。不会复制旧任务和消息，也不会修改原业务行：

```powershell
./scripts/prepare-reading-dev.ps1
./scripts/start-reading-dev.ps1       # 本机 127.0.0.1:18081，关闭旧摄取和旧任务执行器
# 另一个终端，在 frontend 目录：
$env:VITE_USE_MSW = 'false'
$env:VITE_DEV_BACKEND_URL = 'http://127.0.0.1:18081'
npm run dev -- --host 127.0.0.1 --port 5183 --strictPort
```

打开 `http://127.0.0.1:5183/knowledge-bases/8/reading?documentId=15`。开发副本使用现有索引的同名文档编号并再次按数据库副本校验内容；本地原始文件下载不在这个副本的联调范围内。

## 已知边界与待验收

最终工程回归：后端 603 项全部通过（阅读模块 40 项，含 9 项真实 MySQL 用例），前端 32 个文件、178 项全部通过（阅读模块 11 项）。前后端生产构建、前端类型检查、lint 及新增文件格式检查通过。浏览器检查了桌面与窄屏页面、引用和笔记操作。工程测试不等于内容准确率验收。真实模型专题联调及负例见 [联调记录](reading-v1-live-verification.md)。

- 首版核验抽取文本。PDF / DOCX 的图像、图表、复杂公式和扫描识别完整性尚未核验，页面会说明；全面阅读或明确涉及这类内容的任务不会因此声称 FULL。
- 语义支持和目标覆盖仍由模型参与判断，确定性引用校验不能代替内容质量评测。
- 某条候选引用不合格时排除该条，并保留关联目标缺口；合格候选继续语义核验，避免丢弃整批可靠部分。引用不在选定来源、不是逐字摘录或超过长度限制，都不能靠宽松匹配发布。
- 阅读模块重排默认关闭（READING_RERANK_ENABLED=false），不会自动沿用旧 RAG 的外部重排设置。首次实际联调曾继承旧配置调用 Cohere 并收到拒绝，已向用户说明并隔离该默认行为。
- 真实续跑仍出现语义重复。现有精确去重和模型增量约束不能保证消除重复，也不能保证所有说话者、归属和推论都正确，仍需金标及人工检查。
- 每份笔记最多保留 40 条结构化结论和 96 个来源窗口，模型输入有长度上限。达到边界时保存可靠部分并报告缺口，需要缩小或拆分阅读目标。
- 20 道题目前是候选题，尚未形成经审阅的冻结金标，也没有 16/20 的成绩。脚本模型、持久化测试和页面流程测试不能充当内容准确率。
- 2,000 份文档 / 10 万片段的规模测试、论文组复验、实际模型费用和云端性能尚未验证。
- 2026-10-20 用户已授权相关有限原文至 DeepSeek、检索词至阿里云百炼，已执行本机隔离库的风月宝鉴专题联调。额外全文模型测试被自动审批拒绝，未提交；不将专题回答的 FULL 或 1125 个片段的元数据误写为通读全书。
