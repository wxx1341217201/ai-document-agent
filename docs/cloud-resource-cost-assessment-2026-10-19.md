# ai-document-agent 云端开发与部署资源评估

评估日期：2026-10-19（北京时间）。目标是将本项目的代码、编译、调试和服务运行放在云服务器上；当前阶段先核算资源和费用，等待用户决定资源方案。

后续决定（同日）：已选择保留现有 ECS，仅部署前后端，Windows 承担开发、构建和五个依赖服务。下文保留首次评估时点的完整云端开发预算；实际混合部署、SSH 状态与业务验证见 [混合部署说明](hybrid-deployment.md)。本次没有购买或升级服务器。

## 结论

单人、小规模资料库、运行一套完整环境时，优先比较 **4 vCPU / 8 GiB 内存** 的方案。若经常同时运行 Java 语言服务、Maven/前端构建和扫描 PDF OCR，优先考虑 **4 vCPU / 16 GiB**。这是基于当前代码和一次运行快照的工程估算，不是压测得出的容量保证。

当前杭州实例经控制台确认为 2 vCPU / 2 GiB / 3 Mbps，无法直接承载当前完整运行组合及开发工具。增加 Swap 可以缓解部分峰值，不能替代所需物理内存。

项目的 Chat 和 Embedding 通过外部 API 调用，当前不需要为本地大模型推理采购 GPU。

## 资源方案

| 方案 | 适用边界 | 判断 |
| --- | --- | --- |
| 现有 2 GiB | 少量独立服务或拆分组件后的轻量用途 | 无法满足完整云端开发目标 |
| 4 GiB | 调整各进程内存、降低并发，构建安排在别处的运行环境 | 余量小，不作为本次完整开发方案的首选 |
| 4 vCPU / 8 GiB | 单人开发、一套应用与中间件；构建和大文档处理尽量错峰 | 首选比较报价 |
| 4 vCPU / 16 GiB | 开发工具、构建、OCR 同时运行较多 | 更有余量，取决于价差 |

8 GiB 方案落地时仍需设置 JVM 和服务资源预算、降低摄取并发并验证真实文档工作流。现有摄取默认并发为 3、最大 8；OCR 页处理并发默认为 1。尚未更改这些设置。

以上预算针对一套完整环境。若开发后端与部署后端同时常驻，需要另外预算 JVM，并隔离开发/部署的数据库、队列与存储，或明确共享文件和消费关系。当前项目已有“双后端共用队列但文件目录不共享”导致文件读取失败的排障记录，见 `fe14-deployment.md`。

### 模型费用示例

当前示例配置使用 `deepseek-flash` 和 `text-embedding-v4`。以下按公开单价计算，不包含免费额度，不代表本项目已经产生的账单：

- `text-embedding-v4` 北京地域同步调用：0.0005 元/千输入 Token，即 **0.5 元/百万输入 Token**。月处理 100 万 Token 为 0.5 元，1000 万为 5 元；重复建索引、分块重叠和查询改写需要计入实际总用量。[百炼官方价目](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api)
- DeepSeek Flash 当前公开美元价格：未命中缓存的输入为 0.15–0.30 美元/百万 Token，输出为 0.60–1.20 美元/百万 Token，区别为峰谷时段。[DeepSeek 官方价目](https://api-docs.deepseek.com/quick_start/pricing/)
- 若一个月累计 **1000 次模型调用**，每次平均 20000 输入 Token、2000 输出 Token，按全部未命中缓存计算：2000 万输入 + 200 万输出，合计 **4.20–8.40 美元**。该示例按模型调用计数，不能当成 1000 次用户提问的固定费用；查询扩展、Agent 规划、反思、重试都可能产生额外调用。美元金额未按假定汇率换算成人民币，实际以账号计价币种与账单为准。

完整月度成本 = 服务器合同分摊成本 + 未包含的磁盘/带宽/备份费用 + Chat 实际费用 + Embedding 实际费用。个人开发阶段可以先在单台机器上以 Compose 自建这五个依赖服务，再按实测决定是否购买托管数据库等服务。
